# 电力系统基金写作 Skills

本技能包将对话中反复出现的任务拆分为四个可独立触发的 Skill。各 Skill 只处理一种稳定任务，不固化具体项目题目、事故结论、文献编号、文件路径或临时措辞。

## Skills 清单

| Skill | 解决的问题 | 不负责的内容 |
| --- | --- | --- |
| `power-system-grant-prose-polisher` | 在不改变研究实质的前提下润色基金文本 | 重新设计研究方案、核验全部事实 |
| `power-system-grant-chain-auditor` | 审校科学问题、研究内容、方法和输出的闭环 | 文献检索、逐句语言润色 |
| `power-system-grant-evidence-auditor` | 核验政策、数据、事故和文献结论的证据边界 | 创造研究内容、代替专业模型判断 |
| `power-system-grant-slide-compressor` | 将长文本凝练为受字数约束的 PPT 短语 | 补充新方法、改变研究层级 |

## 共通原则

1. 依据用户实际提供的稿件、代码、数据和结果判断，不凭项目题目推测已完成工作。
2. 先检查请求前提、材料完整性和操作模式，再决定诊断、讨论、改写或修改文件。
3. 明确区分可核实事实、作者推断、方法设想和预期结果。
4. 不虚构文献、实验、数据、代码能力、修改结果或文件状态。
5. 用户要求先讨论时，只给诊断与候选方案，不修改文件，不宣称已完成修改。
6. 用户的明确约束优先，例如字数、文献范围、禁用词、是否允许联网和是否允许调整专业内涵。

## 重复与冲突处理

1. 保真润色与链条审校存在交叉时，先判断结构是否成立。结构成立则只润色；结构不成立则先报告断点，获得授权后再重构。
2. 证据核查与语言润色冲突时，证据边界优先。不能用流畅措辞掩盖未核实或过度因果化的结论。
3. PPT 凝练只基于已经确认的正文，不从短语反向创造研究内容。
4. 用户要求保持原意时，不采用会改变研究对象、时间尺度、系统边界或方法角色的改写。
5. 不把一次性偏好固化为普遍规则。只有用户在当前任务明确提出时，才执行特定禁用词、标点或格式约束。

## 推荐调用顺序

涉及完整基金文本时，通常先使用证据核查，再使用链条审校，随后进行保真润色，最后进行 PPT 凝练。用户仅要求其中一步时，只调用对应 Skill。

## 验证

运行 `python3 scripts/validate_skill_pack.py`，检查 frontmatter、触发描述、必需章节和行数限制。
